# Hosting the platform on Render

[Render](https://render.com) can host the platform: the API and the admin portal in one web service, plus
a managed PostgreSQL database. The **hotel connector does not move**. It stays on the Visionline PC and
connects out to the Render address over HTTPS, just as it connects to your PC today. Visionline is never
exposed to the internet.

```
 Staff app ─┐                                     ┌─ Render (Frankfurt) ─────────────────────────┐
 Portal ────┼── https://<name>.onrender.com ────► │ web service: API + portal (Docker)           │
            │                                     │ PostgreSQL (private, no public access)       │
 ASSA ABLOY Credential Services ── callbacks ───► │                                              │
                                                  └────────────────▲─────────────────────────────┘
                                                                   │ outbound HTTPS only
                                         Visionline PC: connector ─┘──► Visionline Web API (local)
```

The repository includes the Render Blueprint `render.yaml`. It describes the following:

| Part | Setting |
|---|---|
| Web service `staff-mobile-key` | The project's `Dockerfile`, region **Frankfurt**, health check `/healthz`, one instance. On every start it applies database migrations and creates **K Hotel Bana with its real settings** (System ID 3460, Mobile Access UUID 9, account `hma-cs-…`), then starts the API. It never creates test accounts. |
| Database `staff-mobile-key-db` | PostgreSQL 16, Frankfurt. It accepts **no connections from the internet**, only from your Render services. |
| Secrets | `JWT_SECRET` and `CALLBACK_SECRET` are generated by Render. The values you type are the first administrator, plus the Credential Services user and password (later). |
| Safety checks | In production the platform refuses to start with development secrets or an `http://` address. |

## Before you start

1. **Choose plans.** Free plans are for a quick look only. Render puts a free web service to sleep after
   15 minutes without traffic, and **deletes a free database 30 days after it is created**. For a pilot,
   keep the paid plans set in `render.yaml` (`0.5c-512mb` web, `0.1c-256mb` database). Prices:
   [render.com/pricing](https://render.com/pricing).
2. **Check data location.** Staff names, emails and the audit trail will be stored in Render's Frankfurt
   region (EU). Check with the hotel that keeping staff data outside Cameroon is acceptable to them, and
   to their legal adviser if needed.
3. **Push the project to a private GitHub repository** ([GIT.md](GIT.md)). `render.yaml` must be in the
   root of the repository.
4. Turn on two-step sign-in for your **GitHub** and **Render** accounts. Anyone in the Render workspace can
   read the service's environment variables, which include the Credential Services password.

## 1. Create the services from the Blueprint

1. Sign in to [dashboard.render.com](https://dashboard.render.com), then choose **New → Blueprint**.
2. Connect GitHub and choose the `staff-mobile-key` repository. Render reads `render.yaml`.
3. Render asks for the values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `BOOTSTRAP_ADMIN_EMAIL` | Your email. It becomes the first platform administrator. |
   | `BOOTSTRAP_ADMIN_PASSWORD` | A new password of 12 or more characters. You will remove it after signing in. |
   | `SECRET_CS_TENANT_USER` | Leave **empty** for now (see step 5). |
   | `SECRET_CS_TENANT_PASSWORD` | Leave **empty** for now. |

4. Choose **Apply**. The first build takes several minutes. When it finishes, the service page shows its
   address, for example `https://staff-mobile-key-ab12.onrender.com`. The **Logs** tab should show:
   ```
   [provision] Created the first platform administrator you@…
   [provision] K Hotel Bana: created; settings added: policy, property, branding, …
   ```

## 2. First sign-in

1. Open the address, sign in with the bootstrap email and password.
2. **Your account → Two-step sign-in**: turn it on.
3. In Render: **staff-mobile-key → Environment**, delete `BOOTSTRAP_ADMIN_PASSWORD`, then **Save changes**.
   Render redeploys the service. The password is then no longer stored anywhere except as your
   account's hash.
4. In the portal:
   - **Settings → Hotel details**: enter the real support email and phone, which the app shows to staff.
   - **Operators**: add the hotel's operators and their roles. Add a Maintenance Manager and Technicians
     if you use Phase 2.
   - **Staff**: add staff, or import a CSV.

## 3. Point the connector at Render

In the portal, open **Connector health → Register a connector**. Name it, for example *Visionline PC*,
and copy the token.

On the Visionline PC, in **PowerShell as administrator**, in the folder of the newest connector zip:

```powershell
Get-ChildItem -Recurse -Filter *.ps1 | Unblock-File
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\install.ps1 -PlatformUrl https://staff-mobile-key-ab12.onrender.com -ResetSecrets
```

- `-ResetSecrets` asks for the **new token** and the status-page password.
- The Visionline address, certificate, read-only mode and watch setting are kept from the previous
  installation.
- The Visionline operator password stays encrypted on the PC. You do not need to send it anywhere.

In the portal, **Connector health** shows the connector *Online*. Then:

1. **Settings → Visionline → Change property credentials**, if the readiness list asks for them.
2. **Run resource discovery**.

On the test PC with the JW Marriott Nairobi Visionline, keep `-ReadOnly -NoWatch` (see
[CONNECTOR-LOCAL-TEST.md](CONNECTOR-LOCAL-TEST.md)). That hotel's doors are then read for the portal,
and nothing is written to its Visionline.

## 4. Point the staff app at Render

Build or start the app with the Render address:

```powershell
$env:EXPO_PUBLIC_API_URL = 'https://staff-mobile-key-ab12.onrender.com'
npx expo start          # in apps\mobile
```

Signed release builds use the same variable (see `apps/mobile/README.md`).

## 5. Credential Services (when K Hotel Bana is ready)

1. **Check the account first, from your PC**, with the read-only check. It only reads and changes nothing:
   ```powershell
   .\scripts\windows\cs-check.ps1 -User k_-_hotel_bana-lhtgdm7qp6jsbsm -SystemId 3460
   ```
2. In Render, under **Environment**, set `SECRET_CS_TENANT_USER` and `SECRET_CS_TENANT_PASSWORD`, then
   choose **Save changes**.
3. After the redeploy, the platform registers its callback address
   (`https://<your address>/integrations/credential-services/callback/k-hotel-bana`) with ASSA ABLOY Credential Services.
   The readiness item **Credential Services callbacks registered** turns green.

The password is typed only into Render's environment. It is never written to the repository, the
database or the logs.

## Updating

- **To update**: push to the `main` branch. Render rebuilds and redeploys automatically, and migrations
  run on start.
- **Rolling back the code**: use Render's **Rollback** on an earlier deploy. A rollback does not undo
  database migrations, so before an upgrade that changes the database, take a backup from the database's
  **Recovery** or backup page in Render. The options depend on the database plan.
- **The connector** is upgraded separately on the Visionline PC, with the new zip and `install.ps1`.

## Custom address (optional)

To serve the platform from your own domain, for example `staffkey.khotelbana.com`:

1. Add the domain under **Settings → Custom Domains** in Render, and create the DNS record Render shows.
2. Add `PUBLIC_URL=https://staffkey.khotelbana.com` under **Environment**.
3. Reinstall the connector with `-PlatformUrl https://staffkey.khotelbana.com`.

## Troubleshooting

| Symptom | What to do |
|---|---|
| Deploy fails with *Refusing to start in production* | A secret is missing or still a development value. `JWT_SECRET` and `CALLBACK_SECRET` must be Render-generated, and `PUBLIC_URL` (if set) must start with `https://`. |
| Log says *No operator exists yet* | Set `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` (12+ characters) and save. |
| Connector *Offline* | On the Visionline PC, check the log `C:\ProgramData\StaffMobileKey\Connector\logs\connector.log`. The PC needs outbound HTTPS (port 443) to `*.onrender.com`. |
| *Credential Services callbacks registered* is red | The user or password is missing or wrong. Run `cs-check.ps1` from your PC. |
